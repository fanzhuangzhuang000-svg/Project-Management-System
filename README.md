# 弱电智能化工程项目管理系统

给弱电/智能化工程公司内部用的一套轻量项目管理系统。围绕 **项目 → 合同（收入/支出）→ 收付款计划 → 收付款 → 发票 → 材料设备** 这条主线，
把「一个项目签了几份合同、该收多少、收了多少、还欠多少、开了多少票、买了多少设备、这个项目到底赚不赚钱」一次算清楚。

三个亮点：

- **扫描件自动识别** —— 合同、发票的 PDF 或照片传上去，自动认出编号、金额、甲乙方、税率、价税合计，自动关联到已有项目和往来单位，一键填表
- **收付款计划与逾期预警** —— 按合同付款条款自动拆成收款节点，实时算出每个节点的冲抵进度，谁欠钱、欠多久一目了然
- **Excel 批量导入** —— 现成的历史台账直接导进来，不用一条条敲

技术上是**零第三方 npm 依赖**：只要有 Node.js 18+ 就能跑，识别用系统自带引擎
（Windows 用内置中文 OCR，Linux 用 Tesseract），不联网、不上云。
Linux 上另需系统包：`apt install tesseract-ocr tesseract-ocr-chi-sim poppler-utils`。

## 零、我该下载哪个？

**三套是同一份程序的三种运行方式，功能完全一致。** 按你的情况选一个：

| 你的情况 | 选 | 下载 | 默认端口 | 需要装什么 |
|---|---|---|---|---|
| **一台 Windows 电脑，自己用** | 单机版 | `elv-pms-*-windows-standalone.exe` | **8787** | 什么都不用（自带 Node 运行时） |
| **局域网多人共用 / 一台常开的机器** | Docker 专业版 | `elv-pms-*-docker.zip` | **8790** | Docker Desktop |
| **自己的 Linux 服务器** | Linux 裸装版 | `elv-pms-*-linux.tar.gz` | **8899** | Node 22 + PostgreSQL（脚本自动装） |

去 [Releases 页面](https://github.com/fanzhuangzhuang000-svg/Project-Management-System/releases) 只下你那一行对应的文件即可。

> ⚠️ **三套的数据互不相通。** 端口不同是为了让它们能在同一台机器上并存，但库是三个独立的
> 数据库（单机版 SQLite、Docker 容器 PostgreSQL、Linux PostgreSQL）。
> 换环境**不会**带走数据 —— 要换请先在旧环境里备份，再到新环境恢复。

**三套怎么并存**：三套可以同时开在开发机上（端口 8787 / 8790 / 8899 各不冲突），
但它们**各写各的库**，别指望数据互通。正式用的时候通常只开一套。

## 一、怎么启动

### 方式一：安装版（推荐，不用装 Node）

双击 **`elv-pms-1.0.0-windows-standalone.exe`**（从 [Releases](../../releases) 下载，约 32 MB），一路「下一步」就行。

> 开发者注：本仓库内 `node tools\build-artifacts.js` 打出的原始文件叫 `dist-installer\弱电项目管理系统-安装程序.exe`，发布到 Release 时重命名为上面的 `elv-pms-*-windows-standalone.exe`。

安装包 32 MB，**已经带好了 Node 运行环境**，目标电脑不需要另外装任何东西。

装完的效果：

- 服务立刻在**后台**跑起来（看不见黑窗口），浏览器直接就能打开系统
- **开机自动启动**，电脑重启后同事照样能访问，不用每次去点
- 桌面和开始菜单都有图标
- 在「设置 → 应用 → 已安装的应用」里能正常卸载

默认装在 `C:\Users\<你的用户名>\AppData\Local\ELV-PMS`，也可以在安装界面里改到别的盘。

装完的目录长这样：

```
ELV-PMS\
├── node.exe            运行环境（自带，不用另装）
├── app\                程序文件
├── data\               你的数据：数据库 + 附件  ★最重要，记得备份★
├── backup\             数据库备份
├── 启动服务.lnk        手动启动（一般用不到，开机已自启）
├── 停止服务.bat        临时停一下服务
└── 使用说明.md         就是这份文档
```

> **卸载不会删 `data` 和 `backup`。** 程序文件删掉，业务数据原地保留，
> 重装或换版本后数据还在。要彻底清掉就手动删整个 `ELV-PMS` 文件夹。
>
> 如果卸载时有文件删不掉（一般是服务还在跑），目录里会留下一个
> `重启后清理.bat`，重启电脑后双击它就能清干净。

### 方式二：免安装（不装 Node 就用这个）

双击文件夹里的 **`启动系统.bat`**。

会弹出一个黑色命令行窗口，两秒后浏览器自动打开 `http://127.0.0.1:8787`，就能用了。

> - 这个黑窗口就是"服务器"，**最小化别关**；关掉窗口服务就停了。
> - 关窗口是**正常退出**，数据会先落盘再关闭，不会丢。
> - 如果 Windows 弹出防火墙提示，勾选"专用网络"并点「允许访问」，否则同事连不上。
> - 这种方式需要电脑上已经装了 **Node.js 22 以上**（系统的数据库组件依赖它）。

### 登录与账号

系统现在需要登录才能使用。**首次启动会自动创建管理员账号**，命令行窗口里会打印出来：

```
┌────────────────────────────────────────────────────┐
│  首次启动，已创建管理员账号：                      │
│      账号： admin                                  │
│      密码： admin123                               │
│  登录后会要求你立刻改成自己的密码。                │
└────────────────────────────────────────────────────┘
```

登录后系统会**强制你先改密码**，改完才进得去。

**忘记密码怎么办？** 在服务器上跑一次（不需要登录）：

```
node tools\reset-admin.js 你的新密码
```

不传参数就重置回 `admin123`。这个命令直接改本地数据库，所以只能在本机执行。

**给同事开账号**：左侧「账号管理」→「＋ 新建账号」。权限按 **模块 × 查看/编辑** 分配：

| 角色 | 权限 |
|---|---|
| **管理员** | 全部模块，含账号管理 |
| **项目经理** | 全部业务模块可读写，可导入、可还原删除 |
| **财务** | 收付款/发票/费用可编辑，合同与项目只读 |
| **只读查看** | 所有模块只能看 |
| **自定义** | 自己勾选每个模块的查看/编辑 |

也可以选「自定义」逐项勾选，比如"只让他管材料设备清单和收付款"。

**权限是怎么生效的：**

- 看不到的模块，**左侧导航里直接不出现**（不是灰掉，是压根没有）
- 只读的模块，进去后**没有新增、编辑、删除按钮**，也没有勾选框
- 权限**在服务端强制校验**，不是靠前端藏按钮——直接调接口一样会被拒（403）

**其它：**

- 会话存在浏览器 Cookie 里，默认 30 天，期间刷新、关浏览器都不用重新登录
- 顶栏右侧有「改密码」和「退出」
- 账号被停用或删除时，**已登录的会话立即失效**
- 登录、退出、改密、建账号都会记进「操作日志」
- 系统会保护管理员：不能删除自己、不能取消自己的管理员身份、不能删掉最后一个管理员



### 给同事用（局域网共享）

启动后黑窗口里会显示一行 `同事访问: http://192.168.x.x:8787`。
把这个地址发给同一办公室的同事，他们用浏览器直接打开即可，**不需要装任何东西**。

若同事访问被拦截，在你这台电脑上用**管理员身份**运行一次命令放行端口：

```
netsh advfirewall firewall add rule name="弱电项目管理系统" dir=in action=allow protocol=TCP localport=8787
```

## 二、模块总览

| 顺序 | 模块 | 作用 |
|---|---|---|
| ① | **往来单位** | 甲方、供应商、分包商、监理的通讯录 |
| ② | **项目台账** | 每个工程建一个项目，是所有数据的归属主线 |
| ③ | **合同管理** | 项目合同（收入）、采购/分包/劳务合同（支出） |
| ③·补 | **合同变更** | 增补/削减/工期范围调整，合同最终金额 = 原金额 + 已确认变更 |
| ④ | **收付款计划** | 按付款条款拆出的收款/付款节点，带逾期预警 |
| ⑤ | **收付款** | 每笔回款、付款登记到对应合同 |
| ⑥ | **发票管理** | 销项（开给甲方）、进项（供应商开来）分开登记 |
| ⑦ | **项目费用** | 材料/人工/分包/机械/差旅等实际支出，用来算**实际成本和动态毛利** |
| ⑧ | **材料设备清单** | 按项目登记采购的设备线缆，跟踪到货进度 |
| ⑨ | **售后维修** | 质保期内的报修与处理记录，区分质保内外 |
| — | **附件与识别** | 集中管理所有扫描件，自动识别并填表 |
| — | **数据导入** | 从 Excel / CSV 批量导入历史台账 |
| — | **回收站** | 删除的记录保留 30 天，随时可还原 |
| — | **操作日志** | 谁在什么时候新增/修改/删除了什么 |
| — | **账号管理** | 建账号、按模块分配查看/编辑权限、登录失败监控与一键解锁 |
| — | **系统设置** | 数据体检、备份、月度快照、附件目录、导出 |

**关键设计：**

- **子系统类别可多选**——一个项目常常同时涉及综合布线、安防监控、门禁、机房等多个系统。
  录入时点选标签（点一下选中、再点取消），列表里以多个标签展示，也能按某个子系统筛出所有相关项目。
- 合同类别选「项目合同」时，收支方向自动变成**收入**；选「采购/分包/劳务合同」时自动变成**支出**。
- **项目台账列表直接显示经营结果**：收入合同额、支出成本、已收款、应收余额（欠款标红）、毛利率，底部有全公司合计行。
  这些数字不落库，每次打开都按最新数据实时算，永远不会对不上账。
- 合同金额填**含税总额**，系统自动折算不含税金额；录发票时税额与价税合计也自动算（想直接填价税合计也行，系统反向推）。
- 毛利按**不含税口径**计算（收入不含税 − 成本不含税），比含税口径更接近真实利润。
- 点项目名称进入**项目详情页**，六个页签：合同 / 收付款计划 / 收付款 / 发票 / 材料设备 / 附件。

### 勾选与批量删除

**每个列表（合同管理、收付款计划、收付款、发票、材料设备、往来单位、项目台账）都能勾选后批量操作。**

- 每行最左侧有勾选框，表头有**全选框**（支持"部分选中"的半选状态）
- 勾选后顶部会出现操作条：**已选 N 条 · 导出所选 · 🗑 批量删除 · 取消选择**，选中的行会高亮
- 点「批量删除」会**先弹确认框**，把关联数据一条条列清楚：

  > 即将删除 3 条合同，其中 1 条存在关联数据：
  > - 收付款计划：4 条
  > - 收付款记录：7 条
  > - 发票：2 条
  > - 附件：3 条

- **有附件的记录会多一个选项**：「☑ 同时删除这 N 个附件的文件」。
  取消勾选就只删记录，**扫描件继续留在「附件与识别」里**（标记为"已解除关联"），以后还能查看下载，
  也**不会被 7 天的自动清理误删**。想留底稿就取消勾选，想删干净就保持勾选。

> 关联数据的处理规则：删项目会连带删除它下面的合同、收付款计划、收付款、发票、材料；
> 删合同会连带删除它的收付款计划节点，并解除收付款、发票、材料的关联（这些记录本身保留）。
> 确认框里都会写清楚，不会有"删了才知道连带删了什么"的情况。

## 三、智能项目分析助手（可接入 DeepSeek 等大模型）

右下角那个助手气泡，**可以接上真正的大模型**，直接问它经营问题。

### 怎么开

「系统设置 → 智能助手」里：

1. 选**模型厂商**（DeepSeek / 通义千问 / Kimi / 智谱 / 豆包 / 硅基流动 / OpenAI / Claude / 本地 Ollama / 自定义）
2. 填 **API 密钥**（界面里有「去申请密钥」的直达链接）
3. 点「**测试连接**」确认能通（这个按钮是边填边测的，不用先保存）
4. 打开「**启用智能助手**」，保存

> **密钥只存在你自己这台电脑上**（`data/ai-config.json`），永远不会下发给浏览器。
> 页面上只会显示 `sk-t••••••••cdef` 这样的掩码。

### 为什么它比通用大模型有用

提问时系统会**自动把当前的经营数据一起发过去**，所以它能回答「我的」问题，而不是泛泛而谈：

| 数据 | 内容 |
|---|---|
| 总体 | 项目数、合同额、回款、应收应付、成本、毛利、开票情况 |
| 应收账龄 | 未到期 / 1-30 / 31-60 / 61-90 / 90+ 分段 |
| 逾期明细 | 每个逾期节点的项目、阶段、金额、到期日、逾期天数、所属合同（**收和付分开**） |
| 计划执行 | 计划节点、已收付、逾期、未到期 |
| 成本构成 | 各科目金额与占比 |
| 项目明细 | 每个项目的合同额、回款、应收、成本、动态毛利、毛利率、成本执行率 |
| 待办预警 | 系统识别出的风险项 |

**数据按你的权限过滤**：只能看项目台账的人，上下文里就只有项目名、状态、进度、负责人，
金额一概不带；也看不到发票、费用这些模块的数据。这一条有专门的测试守着。

### 能问什么

界面里内置了几个快捷提问，也可以自己随便问：

- 哪些项目回款有问题？给我一个催款优先级清单
- 分析一下成本，哪些项目有超支风险？
- 按动态毛利率给项目排个序，说明为什么有高有低
- 应收账龄结构健康吗？该怎么优化？
- 发票和收付款的勾稽有没有异常？税务上要注意什么？

### 今日经营简报（总览页）

配置好之后，**总览页会自动出现一张「今日经营简报」卡片**：模型根据当天数据
写 3 条最该关注的事，每条带数字依据和一个可执行动作，最后给一句整体风险判断。

- 后端**按天缓存**，同一天只调用一次模型，不会反复花钱
- 不同权限的账号各缓存各的，不会串数据
- 卡片上有「重新生成」按钮（有系统设置权限的人才有）
- 没配置大模型时这张卡片**直接不显示**，不占首页地方

### 把分析导出成 Word 报告

每条 AI 回复下面（鼠标移上去）有两个小按钮：**复制**、**导出 Word**。

导出的 `.docx` 是真正的 Word 文档，结构是：

```
经营分析报告                            ← 标题
生成时间 · 模型 · 分析人                 ← 副标题
─────────────────────────────
分析问题      <你问的那句话>
分析结论      <模型的回答，标题/列表/表格/粗体都保留>
────────────────── 分页 ──────────────────
附录：分析所依据的经营数据               ← 当时发给模型的那份数据
```

可以直接打印或发给老板。**这个 .docx 是后端自己拼出来的**——项目没有任何第三方
依赖，所以 ZIP 打包器和 OOXML 都是手写的（`tools/docx.js`）。

### 模型可以自己查明细（工具调用）

不只是把一份数据快照丢给模型。开启后，模型遇到具体问题会**自己去查**：

| 它能查 | 例子 |
|---|---|
| 项目台账 | 「有个叫云鼎的项目是谁负责的？」 |
| 项目全貌 | 「第一人民医院这个项目赚不赚钱？」 |
| 合同明细 | 「这个项目签了几份分包合同？」 |
| 收付款流水 | 「上个月收了多少笔？」 |
| 收付款计划 | 「哪笔验收款什么时候到期？」 |
| 发票勾稽 | 「哪张票开了钱还没到？」 |
| 项目费用 | 「材料费花在哪了？」 |
| 往来单位 | 「华信监理跟我们有多少往来？」 |
| 汇总统计 | 「按负责人排一下合同额」 |

三个好处：

- **能答细节问题**。不再是「只看到汇总」，而是问什么查什么
- **更省 token**。只查需要的那部分，不用每次把全部数据塞进去
- **权限照样把关**。模型看不到你能看的模块——它要查合同但你没合同权限，会被直接挡掉

提问时会显示「正在查询：收付款计划…」，你能看到它在干什么。

> 需要模型支持 function calling。DeepSeek、通义、Kimi、智谱、豆包、OpenAI 都支持；
> **Claude 协议不同，会自动跳过**（仍然能用数据和上下文回答，只是不查明细）。
> 不想要这个行为可以到设置里关掉。

### 每天自动推送到微信 / 钉钉 / 飞书

「系统设置 → 简报推送」里配好，**每天到点自动把经营简报发出去**：

| 推送方式 | 说明 |
|---|---|
| 企业微信群机器人 | 群里所有人都能看到，最省事 |
| 钉钉群机器人 | 支持加签密钥 |
| 飞书群机器人 | — |

## 四、扫描件上传与自动识别

### 在哪里传

1. **录合同/录发票的表单底部** —— 最顺手：传上去、自动识别、点「全部填入表单」，核对后保存。
2. **列表行上的 📎 数字** —— 看某份合同/发票已有哪些扫描件，也能直接补传。
3. **项目详情页的「附件」页签** —— 该项目全部扫描件。
4. **左侧「附件与识别」** —— 集中管理，可以搜索文件名，也能搜索识别出来的文字。

### 支持什么

| 文件类型 | 说明 |
|---|---|
| **PDF**（电子发票、电子合同） | 按 4 倍分辨率渲染后识别，**准确率最高，推荐** |
| **JPG / PNG / BMP / TIF / WEBP**（拍照、扫描件） | 直接识别 |
| Word / Excel / DWG / ZIP 等 | 可以上传存档，但不做识别 |

### 能识别出哪些信息

- **发票**：发票号码、开票日期、发票种类、税率、金额（不含税）、税额、价税合计、购买方、销售方
- **合同**：合同编号、合同名称、合同金额、签订/开工/竣工日期、付款条款、甲方、乙方、工程地点

识别完成后还会自动：

- **匹配往来单位** —— 认出"市第一人民医院"是已有的甲方单位
- **匹配项目** —— 从合同项目名称或发票备注里找到对应项目
- **建议收支方向** —— 甲方开给我们的票 = 销项；供应商开给我们的票 = 进项
- **交叉校验金额** —— 同时读出小写金额和中文大写金额，两者不一致会明确警告
- **保留识别原文** —— 点「看原文」逐字核对

### 识别完怎么落进系统（重点）

识别只是第一步，能一键变成单据才算数。系统做了三条路径：

**① 在表单里上传 → 直接填入**
录合同/录发票时把文件拖进表单底部，识别完点「全部填入表单」，字段、所属项目、对方单位、收支方向一起带进去，核对后保存即可。

**② 没开表单 → 一键建单**
在「附件与识别」或某个记录的附件窗口里点开识别结果，如果当前没有打开对应表单，按钮会变成
**「＋ 新建合同并填入」/「＋ 新建发票并填入」**。点一下会自动打开新建表单，把项目、对方单位、收支方向、各字段全部预填好，你核对后保存——附件也会自动挂到新单据上。

**③ 系统里没有这个单位/项目 → 主动提示新建**
识别出的甲方、供应商或项目名称，如果在系统里找不到，会弹出提示：

> **发现系统里还没有的记录**
> ☑ 往来单位「星海科技园发展有限公司」（甲方）
> ☐ 往来单位「新锐机电安装工程有限公司」（乙方 · 可能是贵司自己，默认不建）
> ☑ 项目「星海科技园智能化弱电工程」

勾选后点「一起新建」，系统会**自动建好并重新匹配**，识别结果里的"系统里没有"立刻变成"已匹配"。
新建项目时还会自动把刚识别到的甲方填成该项目的甲方单位。

> 系统会先按收支方向判断哪一方"很可能是贵司自己"（销项发票的销售方、收入合同的乙方等），
> **默认不勾选**，避免把本公司也建进往来单位里。如果全是不值得提示的，就不会弹窗打扰你。

也可以不理会弹窗，直接在识别结果里点某一项的 **「＋ 新增为单位」** 单独补建。

> 填入时如果某项因为"系统里没有对应记录"没填进去，提示会明确告诉你是哪一项，不会静默失败。

### 拍照的注意事项（很重要）

识别准确率**几乎完全取决于清晰度**。实测结论：

| 图片宽度 | 结果 |
|---|---|
| 1600 px 以下 | ❌ 金额都可能读错，不要用 |
| 2400 px 左右 | ⚠️ 部分字段会错 |
| **3000 px 以上** | ✅ 编号、金额、日期基本全对 |

手机拍纸质件时：**平铺、正面拍、光线均匀**，1200 万像素以上手机直接拍就够了。电子版 PDF/电子发票完全没有这个问题。

> ⚠️ **识别结果只是辅助录入，金额和编号请务必与原件核对后再保存。**

## 五、收付款计划与逾期预警

工程款是按节点收的，这个模块就是管这件事。

### 怎么建计划

最省事的办法：**让系统按合同付款条款自动生成**。

1. 到「合同管理」点开一份合同（编辑界面）
2. 点 **📅 按付款条款生成收付款计划**
3. 系统把条款里的比例拆成节点，日期自动按工期估算

比如付款条款是 `预付款30%，进度款按月度完成量40%，竣工验收25%，质保金5%`，
系统会生成 4 个节点，金额按合同额精确拆分（合计与合同额分毫不差，四舍五入差额落在最后一个节点上）：

| 节点 | 比例 | 计划日期（自动估算） |
|---|---|---|
| 预付款 | 30% | 合同签订日 |
| 进度款 | 40% | 工期中点 |
| 验收款 | 25% | 竣工日期 |
| 质保金 | 5% | 竣工后 12 个月 |

支持**两种写法**的付款条款：

- 比例型：`预付款30%，进度款40%，验收款25%，质保金5%`
- 金额型：`预付176万，进度款234万，验收款147万，质保金29.3万`

比例合计不是 100% 时，系统会给出明确警告，不会闷头算错。生成后每个节点的金额、日期、触发条件都可以手工改。

### 状态是怎么算的

**不需要逐笔勾稽**。系统把同一个项目、同一方向的实际收付款，按计划日期先后**自动冲抵**各节点：

- 已收付 / 未收付金额
- 状态：`待收付` / `部分收付` / `已完成` / `已逾期`

这样任何时候都不会出现"计划没销账"的糊涂账。实际收款比计划早或晚都不影响，只看总额冲抵进度。

> 数据自洽性：`计划收款合计 − 已收付 = 应收余额`，三者始终对得上。

### 总览页的预警

- **⚠️ 逾期未收 / 未付的计划节点**：按逾期天数排序，谁欠钱、欠多久、欠多少一目了然
- **未来 6 个月收付款计划**柱状图：提前看出哪个月资金紧张
- KPI 里的「本月计划收款」「逾期未收（按计划）」

## 七、实际成本与动态毛利

**这是整套系统里最该看的数字。**

签合同时算出来的毛利是「预期」：收入合同额 − 支出合同额。但实际会多出很多东西——
材料实际采购价、人工、机械租赁、差旅、招待、税费、现场经费。所以「项目费用」模块专门记这些。

### 两个毛利，看哪个都行

| 指标 | 算法 | 用途 |
|---|---|---|
| **预计毛利**（合同口径） | 收入合同额(不含税) − 支出合同额(不含税) | 签约时的预期，用来判断这单接得值不值 |
| **动态毛利**（真账口径） | 收入合同额(含税) − **实际发生成本** | 项目做到现在到底赚不赚钱，随时在变 |

### 费用怎么记

「项目费用」按科目登记，每个科目都有实际发生额：

材料设备 · 人工费 · 分包费 · 机械租赁 · 差旅交通 · 业务招待 · 税费 · 现场经费 · 其他

每笔填：金额（含税）、税率（选填，有专票时填，自动折算不含税）、发生日期、收款方、有无发票、已付/未付。
发票和收据的扫描件可以直接传在费用记录上。

### 成本执行对比

系统还会拿**实际成本**和**支出合同预算**比：

> 预算 469 万 · 已用 98.9% · 结余 5.2 万

一眼看出这个项目的成本是超了还是省了。总览页还有「实际成本构成」饼图，看清钱花在哪个科目上。

## 十三、总览页能看什么

总览页是一块**深色数字孪生驾驶舱**（其余业务页面保持浅色，方便录入）。打开就自动刷新时钟，数字带滚动动画。

版面自上而下四层，越靠上越重要：

### 第一层 · 四个核心指标
大号发光数字，一眼看清经营状况：

| 指标 | 含义 |
|---|---|
| 收入合同额 | 附回款进度条、合同份数、不含税额 |
| 实际成本 | 附预算使用进度条、成本执行率 |
| 动态毛利 | 真账口径，附毛利率与预计毛利对比 |
| 应收未收 | 附逾期金额、应付金额（含零星未付） |

### 第二层 · 待办提醒
单行紧凑色块，按紧急度排序（红 → 橙 → 青）：逾期未收/未付、7 天内到期、30 天内到期、
质保金到期、竣工未收齐、售后待处理、已开票未收、已收未开票、零星费用未付。
点任意一条直接跳到对应页面去处理；超过 6 条时收起为「还有 N 条」。
侧栏「总览」和「收付款计划」上还有红色数字角标。

### 第三层 · 三个业务分区

版面分成 **资金 / 经营 / 项目** 三个分区，每区有标题分隔线。同一行的卡片**等高**、每行**正好铺满**，不留空档。

**资金**
- **账龄分析** —— 应收/应付按 未到期 / 1-30 / 31-60 / 61-90 / 90+ 分档，颜色由绿到红
- **资金流水** —— 一张卡两半：左「过去 12 个月·实际」，右「未来 6 个月·计划」，
  一根时间轴从已发生接到计划中；鼠标悬停看当月具体金额
- **30 天内到期的款项** —— 通栏逐笔列出到期日、项目、节点、倒计时（3 天内红、7 天内橙）

**经营**
- **关键比率** —— 回款率 / 成本执行率 / 动态毛利率 / 开票覆盖率，环形按比例填充 + 发光
- **经营趋势** —— 来自每月自动快照，三条线（动态毛利 / 应收未收 / 实际成本）
- **实际成本构成** —— 占比最大的 4 个费用科目 + 「其他」（完整明细在「项目费用」页）
- **发票与收款勾稽** —— 见「十二·补」第 3 条

**项目**
- **应收余额排行** —— Top 5，前三名有金银铜徽标
- **逾期最久的款项** —— 按逾期天数倒序，90 天以上标红
- **子系统合同额分布** —— 一个跨系统的项目会分别计入它涉及的每个子系统，所以各项合计会大于总合同额
- **项目与售后** —— 项目状态分布 + 待处理售后单数

> **版面为什么这样排**：早期版本 12 张卡片平铺、没有分组，同排卡片高度从 116px 到 416px 不等，
> 还有一行右侧空出 951px。现在按业务分区、同排等高（最大高差 0px）、每行铺满（空洞 0px），
> 整页高度从 2119px 压到 1600px。这几条都写进了前端界面测试，改版时若再排乱会直接报错。

> 想让同事只看数据不改数据，就给他开一个「只读查看」账号——大屏照看不误，但改不了任何东西。
> 没有某个模块的查看权限时，对应面板显示「无权限查看」而不是数字。

## 十三·补、八项经营闭环增强

这一节对应"整体检查后可优化方向"的落地结果。

### 1. 登录限速

- 同一**账号** 15 分钟内错 5 次 → 锁定 10 分钟
- 同一**来源 IP** 15 分钟内错 20 次 → 锁定 10 分钟（阈值放宽，避免一个人手滑把同事一起锁住）
- 锁定期间前端按钮变成倒计时，不会让人反复试
- 「账号管理」页顶部显示失败监控，管理员可一键**解除锁定**，不用等 10 分钟

### 2. 计划到期预警

收付款计划节点按到期日自动分档（7 天内 / 8-30 天 / 90 天内质保金），
汇总到总览的待办提醒条和「30 天内到期的款项」明细表，侧栏带红色角标。

### 3. 发票与收款勾稽

收付款上多了一个「**对应发票**」字段，可以精确挂账。勾稽用**双口径**：

| 口径 | 算法 | 特点 |
|---|---|---|
| **总额勾稽**（主） | 已开票未收 = max(0, 开票额 − 收款额)；已收未开票 = max(0, 收款额 − 开票额) | 不用填任何东西就准 |
| **逐笔挂账**（辅） | 汇总挂到每张票上的收付款金额 | 填了更精确，发票列表显示「已收付/未收付」 |

发票页有「🔗 自动关联收款」按钮：按 **项目 + 合同** 把没挂账的收付款匹配到开票日期最早的发票上，
只在"这张票还差的钱 ≥ 这笔款"时挂，**绝不会挂出负数**，手工填过的记录不覆盖。

### 4. 费用未付计入应付

应付账款拆成两个口径，避免重复计算：

```
应付 = 支出合同的未付款（合同额 − 已付款）
     + 无合同的零星未付费用（人工、差旅等）
```

已付状态的费用不进应付；挂在合同下的费用也不重复计入（合同口径已经算过）。

### 5. 合同变更 / 补充协议

新增「合同变更」模块（📝）。增补、削减、工期/范围变更都记成独立记录：

- 合同 **最终金额 = 原金额 + 已确认变更的增减额**
- **只有「已确认」状态计入**，草稿和已作废不算
- 削减金额填负数
- 项目统计、大屏、毛利一律按**最终金额**算（没有变更时等于原金额，历史数据口径不变）
- 删合同不会删变更记录，只解除关联（变更本身是发生过的事实）

### 6. 月度结账快照

账龄、应收这些是"按今天实时算"的，过了月就算不出上月了。所以：

- 服务启动时若上个月没有快照，**自动补记**一份（标注"自动补记"）
- 「系统设置」可手动「📸 立即记一份」、查看历史、删除某月
- 大屏「经营趋势」折线来自这些快照，最多保留 60 个月

### 7. 大屏图形增强

用**纯 SVG 手绘**，没有引入任何第三方图表库（保住零依赖、断网也能用、配色风格统一）：
环形仪表（按比例填充 + 发光）、趋势折线（渐变面积 + 数据点 + 悬停提示）。

### 8. 手机端适配

- 侧栏收成**抽屉**，顶栏汉堡按钮开关，点遮罩/切页面自动收起
- 宽表格**横向滑动**，操作列吸附在右侧
- 表单单列、弹窗占满屏、输入框放大到 15px（避免 iOS 自动缩放）
- 导航项高度 54px、按钮最小 34px，手指点得中
- 390×844（iPhone 12）实测无横向溢出

## 十四、数据在哪，怎么备份

```
elv-pms\data\pms.db                数据库（合同、收付款、发票、材料等全部业务数据）
elv-pms\data\attachments\          附件扫描件原件
```

**备份：双击 `备份数据.bat`**，一次搞定两件事：

- `backup\pms_日期_时间.db` —— 数据库副本（用 SQLite 的 `VACUUM INTO` 生成，完整、一致、已整理）
- `backup\attachments_时间戳.zip` —— 全部扫描件打包

建议每天收工前点一次，再把 `backup` 里的文件复制一份到网盘或移动硬盘。
系统自动保留最近 30 份数据库备份；附件包较大，请自行清理旧文件。

**「系统设置」里还有「立即备份」按钮**，一键备份数据库（不含附件），适合频繁使用。

**数据安全机制：**

- SQLite **WAL 模式 + `synchronous=FULL`**，断电或强制结束进程都不会丢已保存的数据
- 正常关闭窗口时先做检查点落盘再关闭连接
- **每天首次启动自动备份一份**，防止误删除、误操作
- **启动时自动做一次数据自检**：清掉「父记录已不存在」的孤儿行（比如某合同被删后残留的计划节点）。
  这类数据界面上看不到，却会让统计虚高；只删父记录确实缺失的行，不碰正常数据，清理结果会打印在启动窗口里
- **登录会话存在 httpOnly Cookie 里**，默认 30 天，前端脚本拿不到，降低被盗用风险
- **删除的记录自动进回收站**，保留 30 天可还原，不会一删就没
- **只在全新数据库上写示例数据**：老库即使被清空也不会自动补示例数据（否则"数据丢失"会被伪装成"正常初始化"）；
  启动时还会把各表记录数打印出来并追加到 `data\startup.log`，方便回溯
- 「系统设置 → 数据体检」随时可看各表记录数、数据库体积、上次备份时间

**换电脑：** 把整个文件夹拷过去即可，`data` 目录里的两样东西都在其中。

**导出给财务/老板看：** 每个列表右上角有「导出」按钮导出 CSV，双击用 Excel 打开即可二次统计。

### 备份格式：不同后端不一样（重要）

「系统设置 → 数据安全」里会直接显示当前用的备份格式。这一栏不是装饰 ——
不同数据库下备份的**完整性完全不同**，看错了会误判数据安不安全。

| 数据库 | 备份格式 | 包含内容 | 怎么还原 |
|---|---|---|---|
| SQLite（单机默认） | `VACUUM INTO` 原生副本 | 表结构 + 数据 | 把 `.db` 文件放回 `data` 目录 |
| PostgreSQL | **`pg_dump -Fc`** | 表结构 + 数据 + **索引 + 约束 + 序列** | `node tools/restore-backup.js` |
| PostgreSQL（找不到 `pg_dump` 时） | JSON（⚠ 降级） | **只有数据，没有结构** | 只能手工导入，见下 |
| PGlite（测试用） | 数据目录 `.tar.gz` | 整份数据目录 | 停止服务后解压回数据目录 |

⚠️ **`pg_dump` 缺失时系统会自动降级成 JSON，并在界面上明确标红提示。**
这不是小问题：JSON 只有行数据，主键、索引、唯一约束、默认值全都没有。
所以部署到 Linux 时**必须装 PostgreSQL 客户端**：

```bash
sudo apt install postgresql-client
```

`deploy/deploy.sh` 会自动装上并检查。如果没装，备份仍能生成，但只有数据、没有结构。

### 从备份还原

**还原前必须先停服务** —— 覆盖一个正在被使用的数据库，SQLite 会锁死、PG 会写坏。
还原工具本身不负责停服务，因为它跑的时候服务多半还活着。

```bash
# Linux / 裸机
sudo systemctl stop elv-pms
sudo -u elv-pms node /opt/elv-pms/tools/restore-backup.js            # 用最新一份
sudo -u elv-pms node /opt/elv-pms/tools/restore-backup.js pms_20261007_031700.db  # 指定某份
sudo systemctl start elv-pms

# Windows 单机版：先把「启动系统」窗口关掉，再跑
node tools\restore-backup.js
```

工具会先把**当前**数据另存为 `..._before-restore.db` 再动手，还原错了还能退回去。

拿到一份 JSON 兜底备份怎么办（没有 pg_dump 的情况下才有）：

```bash
node tools\restore-backup.js pms_20261007.json
```

会列出里面有多少张表、多少行，并说明这份不能一键还原 —— 需要导出成 CSV，
再用系统的「数据导入」功能导进去。更好的办法是装上 `postgresql-client` 重新备一次。

## 十四·补、Linux 裸机部署（不用 Docker）

给「客户自己买一台云服务器」的场景准备的一套东西，已在 Ubuntu 26.04 + PostgreSQL 18 上实测跑通。

### 一条命令装好

```bash
sudo ./deploy/deploy.sh
```

脚本会做完这些事：装依赖（Node、**postgresql-client**、tesseract 中文引擎）→ 建 `elv-pms` 系统账号 →
装程序到 `/opt/elv-pms` → **随机生成数据库密码**并写进 `/etc/elv-pms/elv-pms.env`（权限 600）→
建库建账号 → 装 systemd 服务和备份定时器 → 启动并自检。重复执行安全，不会清数据。

### 关键设计

- **程序不以 root 跑**：systemd 里 `User=elv-pms`，只对 `data/` 和 `backup/` 可写
- **崩溃自动拉起**：`Restart=always`，但连续失败 5 次就停下来，不无限重启刷屏
- **内存上限 768MB**：Node 默认按物理内存算堆上限，在 2G 云主机上很容易被 OOM Killer 干掉
- **数据库重启/网络抖动会自愈**：连接断了自动重连（实测 PostgreSQL 重启后第一次探测即恢复）

### 日常运维

```bash
systemctl status elv-pms                    # 状态
journalctl -u elv-pms -f                    # 实时日志
systemctl restart elv-pms                   # 重启
systemctl list-timers elv-pms-backup.timer   # 下次自动备份时间

# 手动备份 / 还原
sudo -u elv-pms node /opt/elv-pms/tools/backup.js
sudo -u elv-pms node /opt/elv-pms/tools/restore-backup.js
```

### 自动备份

每天 **凌晨 3:17** 自动跑一次（刻意避开整点，整点磁盘 IO 竞争最激烈）。
关机/休眠错过的会在开机后补跑。保留最近 30 份。

⚠️ **自动备份只备数据库，不备附件。** 附件在 `data/attachments`（本地存储）或 MinIO（对象存储）。
用云服务器时建议把数据目录整个挂到云盘，或者给 `backup` 目录配一条对象存储同步。

### 云上的必做事项

1. **安全组放行端口**（脚本只管 `ufw`，云厂商安全组要去控制台开）
2. **数据盘**：程序装在系统盘，数据目录 `data/` 和 `backup/` 建议挂独立云盘 ——
   实例重装时系统盘会丢，独立数据盘能保留
3. **`/etc/elv-pms/elv-pms.env` 权限必须是 600**（里面有数据库密码）

### 端口

默认 `8899`，改法是编辑 `/etc/elv-pms/elv-pms.env` 的 `PMS_PORT` 后 `systemctl restart elv-pms`。

> ⚠️ **本机开发时裸装版用的是 8791，不是默认的 8899** —— 因为开发机上同时跑着
> 三套环境（单机版 8787 / Docker 专业版 8790 / 裸装版 8791），端口必须错开。
> 客户部署时用默认值 8899 即可，互不干扰。完整对照表见 `部署检查清单.md`。

## 十六、常见问题

**Q：提示端口 8787 被占用？**
说明已经有一个实例在跑了。直接用浏览器打开 `http://127.0.0.1:8787`，或先关掉那个命令行窗口。
也可以指定其它端口启动：`node server.js --port 8899`。

**Q：忘记登录密码了？**
在服务器上运行 `node tools\reset-admin.js 新密码` 重置管理员密码（不需要登录，只能在本机执行）。
不带参数就重置回 `admin123`。普通账号忘了密码，让管理员到「账号管理」点「重置密码」即可。

**Q：同事说看不到某个模块？**
到「账号管理」检查他的权限——没授权的模块在他那边**导航里压根不显示**。这是设计如此，不是 bug。

**Q：识别一直显示"识别中"？**
单个文件通常 2~5 秒。多页 PDF 会逐页识别，会久一些。长时间没反应就到「附件与识别」点「重新识别」。

**Q：生成收付款计划时说"没有读到付款比例"？**
说明这份合同的「付款条款」字段里没写比例。补充成 `预付款30%，验收款65%，质保金5%` 这样再生成。

**Q：示例数据要留着吗？**
首次启动会写入 3 个示例项目（编号以 `DEMO-` 开头，列表左侧有黄色竖条标记）。正式使用时到「系统设置」点
**🧹 一键清空全部示例数据**，只删示例，不影响你自己录入的数据。

**Q：导入时提示找不到往来单位？**

- 数据模型单一来源：`schema.js` 的字段定义同时决定**建表**、**接口校验**和**前端表格/表单**。
  加字段只需在对应表 `fields` 里加一行，重启服务三处同时生效（实时汇总的列加 `virtual:true`）。
  React 端的表格列和表单控件同样是由 `/api/meta` 返回的 schema 驱动，加字段不用改前端代码
- 数据库：WAL + `synchronous=FULL` + `busy_timeout`，备份用 `VACUUM INTO`

### 性能与规模（已做的优化）

系统是按 2-5 人办公室设计的，但数据会逐年累积。下面这几处是实测出来的瓶颈，已经处理掉，
`tools/perf-test.js` 会守住不让它们退化：

| 问题 | 优化前 | 优化后 |
|---|---|---|
| `/api/dashboard` 的 SQL 条数（400 个项目） | **4046 条**（每项目一组查询） | **24 条**（每表一条分组查询） |
| `/api/dashboard` 耗时（400 个项目） | 205 ms | 62 ms |
| 项目台账列表取 20 条 | 145 ms（查全表 + 逐行算统计） | 12 ms |
| 收付款列表取 20 条 | 15 ms | 5 ms（LIMIT 下推到 SQL） |
| `/api/meta` 下拉选项体积（400 个项目） | 529 KB | 136 KB |
| 登录页首屏（真实浏览器实测） | 193 KB（gzip） | **88 KB**（gzip） |

具体做法：

- **项目统计批量化**：`projectStatsMany(ids)` 把「每个项目跑一组查询」改成「每张表一条
  `GROUP BY project_id` 查询」，无论多少项目都是固定 8 条 SQL
- **分页下推到 SQL**：以前是读全表再在内存里 `slice`，现在 `LIMIT/OFFSET` 交给数据库，
  只把当前页读出来再装饰
- **下拉选项只下发用得到的表**：收付款、项目费用、材料设备这些表从来不作为外键目标，
  它们的选项占了八成体积却没人用，现在按 schema 的 ref 字段自动算出该下发哪几张
- **前端按路由分包**：图表库 Recharts 有 400 KB，登录页用不到，
  改成路由级 `React.lazy`，进总览时才加载

> 加新功能时注意两点：别在循环里跑查询（用批量版），别把 `LIMIT` 留在 JS 里做。
> `perf-test.js` 会检查这两件事。

#### 深色主题怎么改颜色（三条铁律，踩过两次坑）

深浅主题全靠 `src/index.css` 里 `:root` / `html[data-theme='dark']` 两组 CSS 变量驱动，
组件里 **不要写死颜色类**：

1. **表面用语义名**：`bg-surface`（卡片/弹窗/下拉）、`bg-subtle`（次级块）、
   `bg-subtle-strong`（三级块 / hover）、`bg-track`（进度槽、分隔线）。
   `bg-white` / `bg-slate-50` / `bg-slate-100` 在浅色主题下看不出问题，
   切到深色就是一块刺眼的白斑 —— 这是本系统最常见的回归。
2. **颜色变量写成 RGB 三元组**（`--c-surface: 30 41 59`），不要写 `#1E293B`；
   只有这样 `bg-surface/70` 这种透明度写法才生效。
3. **彩色底直接用 Tailwind 名字**：`bg-red-50` / `text-red-600` / `border-red-200`
   这几个「当底色和当彩色字」的档位已经接到变量上了，深浅自动切换，
   不需要写 `dark:` 变体。目前映射了 red / amber / orange / blue / green /
   emerald / violet / cyan 八个色调；用别的色调（如 `yellow-50`）要先到
   `index.css` 里补 `--c-yellow-*` 变量，否则它不跟主题。

改完**必须跑**这个审计（无头 Edge 全量扫，会按「元素实际合成亮度」找残留）：

```bash
node tools/ui-theme-audit.js --themes=dark,light --shot   # 有亮色残留则退出码 1
node tools/ui-theme-audit.js --palette                    # 打印两套主题的色板快照
node tools/ui-theme-audit.js --pages=settings --layout     # 量卡片底部留白、栅格空洞
```

`--layout` 是给「页面留白太多」这类问题用的：它会报出每张卡片内部底部空了多少像素。
**栅格容器务必带 `items-start`** —— 不加的话同排的矮卡会被拉伸到最高卡的高度，
内部留下一大片空白（系统设置页曾因此空出 576px）。


### 打包成 exe（怎么重新生成安装包）

```bat
node tools\build-installer.js
```

产物：`dist-installer\弱电项目管理系统-安装程序.exe`

做法上**不依赖 Inno Setup / NSIS / 7-Zip**，只用 Windows 自带的 .NET 编译器：

1. 把 `node.exe`（83 MB）+ 后端模块 + `public/` 暂存成一个目录
2. 压成 zip（83 MB → 32 MB）
3. 用 `csc.exe` 把 C# 写的安装程序编译成 exe，zip 作为**内嵌资源**打进去
4. 运行时 `ZipArchive` 解出来

安装程序只有三个文件：

| 文件 | 作用 |
|---|---|
| `tools\installer\Installer.cs` | 安装程序本体（WinForms 向导 + 静默安装 + 卸载） |
| `tools\make-icon.js` | 生成图标。**纯 Node 手绘像素 + 自编码 PNG/ICO**（这台机器上 `System.Drawing` 加载不了，所以没用它） |
| `tools\build-installer.js` | 打包脚本 |

改完 `Installer.cs` 后加 `--reuse` 可复用压缩包，省掉每次 4 秒的压缩。

**验证安装包**（强烈建议每次改完都跑）：

```bat
node tools\verify-installer.js
```

它会真的装一遍、启动服务、登录、上传扫描件验证识别引擎、
然后卸载并检查数据是否保留，一共 42 项。

> ⚠️ 这个验证脚本必须从**工作区之外**运行安装程序——脚本会自己把 exe 复制到
> `%TEMP%` 再执行。原因见下面「关于沙箱」。
>
> ⚠️ 运行 PowerShell 脚本时注意编码：本机 PowerShell 5.1 默认按 ANSI 读 `.ps1`，
> 含中文的脚本必须存成 **UTF-8 带 BOM**，否则中文会被拆坏导致语法错误。
> `.bat` 文件则相反，必须存成 **GBK**。

### 关于沙箱（装 exe 时会踩到的坑）

本会话的文件沙箱会限制**从工作区启动的进程**往工作区以外写文件。
表现是：从 `dist-installer\` 双击/运行安装程序，`Directory.CreateDirectory`
会抛 `UnauthorizedAccessException`，看起来像代码 bug，其实是环境限制。

判别方法：把同一个 exe 复制到 `%TEMP%` 再运行，就一切正常。

> 这一点已按 `diagnose-windows-sandbox-acl` 技能确认：**"工作区之外的写入被拒"属于预期行为，
> 不是文件权限损坏**，因此没有做权限修复。真实用户双击安装不会遇到这个问题。

### 授权（离线授权码 · 按公司授权）

「系统设置 → 授权」里粘贴授权码。授权码绑定**公司名 + 到期日期 + 账号数上限**，离线校验，不需要联网。

> **为什么不再一机一码**（2026-10 改）：部署形态从「装在客户自己电脑上」变成
> 「跑在云服务器/客户自购服务器上」。云主机的网卡是**弹性网卡**，重装系统、
> 换可用区、跨云迁移，MAC 就会变——按机器码锁会把客户在续费时锁在门外。
> 原来的 pin 宽限也救不了：pin 只存在数据盘，云盘重建就没了。

生成（**只给卖软件的人用，不会打进安装包**）：

```bat
node tools\gen-license.js "客户公司名" 2027-12-31                     :: 不限账号数
node tools\gen-license.js "客户公司名" 2027-12-31 --seats=20          :: 最多 20 个启用账号
node tools\gen-license.js --check ELV3.xxx.yyy                       :: 校验一个已有的码
node tools\gen-license.js                                             :: 不带参数进入问答模式
```

出码后要提醒客户：到「系统设置 → 界面自定义」把**公司名**填成和授权码一致，
否则会提示「授权码是发给某某公司的」。

行为：

| 状态 | 表现 |
|---|---|
| 未填 / 填错 | 功能不受限，只是提示（否则新装和打错字都会把客户锁在门外） |
| 公司名对不上 | 提示无效并给出该改成什么（**不锁写**） |
| 到期前 30 天 | 顶部橙色提醒条，可关掉 |
| 已过期 | 顶部红色提醒条不可关；**能看、能导出、能备份**，只是不能再录入 |
| 达到账号数上限 | 顶部橙色提示；**不能新建账号**，但已有账号照常登录、照常改数据 |

账号数上限的规则：

- 只数**状态为「启用」**的账号，停用的不占额度（停人＝腾位置）。
- 达上限时**只拦新建账号**，改权限、停用、删除、重置密码全部放行——
  绝不能因为额度用完把客户锁在门外。
- 额度用完后系统照常可用，**只是不能再加人**。

老码兼容：

- `ELV1`（公司名 + 到期日）、`ELV2`（曾一机一码，公司名 + 到期日 + 机器码）
  **继续有效**——已发出去的码不会因为这次改造作废。
- ELV2 码里的机器码**不再比对**（反正云上也没有稳定的机器码），
  但格式仍要合法，非法格式照样判无效。

> **安全边界（请如实理解，不要高估这套保护）**
> 这是**离线签名**，不是加密：密钥内置在软件里，理论上能被逆向出来自己造码。
> 放弃机器绑定后，一份码可以被复制到任意多台机器——**这是离线校验的固有上限**，
> 不是实现缺陷。真正能约束部署数的只有**联网激活**（要维护一台服务器，
> 且客户内网不通外网时就不能用）。
> 这套能可靠做到的：**到期转只读**（年费收得回）+ **账号数上限**（一家买不了全家用）。
> 「整包复制给别家公司」属于商业信誉问题，靠合同和售后解决，不指望技术。
>
> 换密钥：设环境变量 `PMS_LICENSE_SECRET`，**签发端和所有部署端要一致**
>（换了之后所有已发出的码全部失效）。⚠️ 别把它写进客户的 `.env`——
> 客户读到密钥就等于能自己造码。


### 识别是怎么工作的（两条通路）

上传的文件会先判断「有没有文字层」：

| 文件类型 | 走哪条路 | 特点 |
|---|---|---|
| 电子发票等**数字生成**的 PDF | **PDF 文字层**（pdfjs，Apache-2.0） | 原文照搬，**100% 准确**，约 25–150ms |
| 拍照/复印的**扫描件** | **Windows OCR**（Windows）／**Tesseract**（Linux） | 看图认字，慢一些，受清晰度和公章遮挡影响 |

判断依据是文字层内容少于 80 字就认为「没有文字层」，自动回退到 OCR。

**为什么值得分两条路**：电子发票 PDF 里本来就有准确文字，
渲染成图片再 OCR 会把「电子发票（增值税专用发票）」读成碎片、
把单价粘成 `1.007262.805309734514`（曾因此算出 1e18 的金额）。

识别结果面板里会标明用的哪条通路：
`文字层 · 精确` 或 `OCR 识别`。

#### 识别引擎：Windows 与 Linux 自动切换

`tools/ocr-backend.js` 在启动时探测可用引擎，两边输出**完全相同**的结构，
下游抽取和前端不用改一个字。

| 平台 | 引擎 | 依赖 |
|---|---|---|
| Windows | `tools/ocr.ps1`（PowerShell 5.1 + WinRT 内置 OCR） | 无，随系统自带 |
| Linux | `tesseract` + `poppler-utils` | `apt install tesseract-ocr tesseract-ocr-chi-sim poppler-utils` |

- Linux 缺哪个包，启动横幅会直接提示（`⚠ 缺少中文语言包…`），不会静默失败。
- 引擎状态也能从 `/api/meta` 的 `ocr` 字段读到（`ok` / `engine` / `label`），云上排查方便。
- 强制指定引擎用 `PMS_OCR_BACKEND=tesseract|powershell`；Tesseract 不在 PATH 用 `PMS_TESSERACT_PATH`。

**Linux 侧的两个关键参数**（都是实测踩出来的，别随手改）：

1. `--psm 6`（统一文本块）。默认 psm 3 会把中文表单项切碎成
   「FS (RBA)」「ABSA (AR)」，甲方乙方直接丢失；psm 6 才能读出
   「甲方 (发包方) : 市第一人民医院」。
2. 中文通道**只用 `chi_sim`，不要 `-l chi_sim+eng`**。混语言会让中文标签崩坏
   （同上）。数字由独立的 `eng` + 数字白名单通道负责，两条路各司其职。

**金额兜底**：实测 `chi_sim` 会把小字号金额读错（`5,860,000.00` → `9,.860,000.00`），
而同一张图的 `eng`+数字白名单通道读得完全正确。因此当中文通道没抽出金额时，
会用数字通道的候选补上，并在界面上挂一条**请核对原件**的提示——
数字通道输出没有上下文，不能当作已确认的值直接入库。

扫描件识别质量参考（3400×4661 合同扫描件）：7/7 字段、金额正确，
但「项目名称」里的「智能化」可能被读成「知能化」，付款条款末尾可能读成「质保人多 59%」，
这类字词错误不影响建单，请对着原件核对。

#### 发票抬头是「左右两栏」，名称必须按标签截断

电子发票的购买方/销售方是并排两栏，PDF 文字层会把同一行的两栏拼成一条：

```
购 名称：上海甲杰电子信息系统有限公司 销 名称：上海乙维电子科技有限公司
买 售
方 方
```

而归一化为了修「发 票 号 码」这类 OCR 噪声，会删掉汉字之间的空格 —— 两栏于是连成一片。
早期版本按「名称标签后面接 40 个字符」取值，结果**购买方名称把销售方的标签和名字整段吞了进来**
（线上真实票据：购买方 = `上海甲杰电子信息系统有限公司销名称:上海乙维电子科技有限公司`，
一个 31 字的假公司名）。

现在名称一律在**下一个字段标签**处截断（`销名称`／`统一社会信用代码`／`价税合计`…）。
「地址/电话/开户行/账号」这类词可能是真实公司名的一部分（如「上海电话设备厂有限公司」），
只有后面跟着冒号才当标签；标签找到了但值被截空时**宁可留空让你手填**，也不退到更松的规则去抓一个假名字。
回归测试：`tools/invoice-party-test.js`（22 项，覆盖真实版式、反序版式、缺字标签、误截风险）。

### 权限模型（v1.1 加固）

所有接口在服务端按「表 × 读/写」逐一守卫，前端隐藏只是锦上添花：

| 数据出口 | 守卫规则 |
|---|---|
| 列表 / 单条 / 导出 / 详情 / 对账单 | 该表有读权限才放行 |
| 保存 / 删除 / 批量删 / 生成计划 | 该表有写权限才放行 |
| 全局搜索 | 结果按各表读权限过滤，无权的表搜到也不返回 |
| 附件（下载/列表/识别/重匹配） | 管理员任意看；普通用户按附件所属表的读权限 |
| 附件（上传/删除） | 按附件所属表的**写**权限（比查看更严） |
| 驾驶舱总览 | 无权模块的数字直接不返回（前端显示「无权限查看」） |
| 回收站 / 日志 / 账号 / 导入 / 备份 / 设置 | 独立的 sys 权限 |

> 给采购员开「只能看材料设备」的账号，他登录后看不到合同额、毛利、应收——驾驶舱对应区域显示「无权限查看」而不是数字。
